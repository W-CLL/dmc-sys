# 饭点时间Job执行控制指南

## 问题理解

用户的真实需求是：**队列中已经有很多任务了，但是在饭点时间（12:00-13:30）希望执行得不那么频繁**，而不是限制生成的任务数量。

## 解决方案

在Job执行层面进行控制，而不是在任务生成阶段。当Job开始执行时，检查是否为饭点时间，如果是则应用特殊的执行策略。

## 🍽️ **饭点时间Job执行控制机制**

### 1. **执行时机检测**
- 在每个Job开始执行时检查当前时间
- 自动识别12:00-13:30的饭点时间
- 只在饭点时间应用特殊控制策略

### 2. **三重控制策略**

#### A. **概率性跳过执行（70%概率）**
```php
if (rand(1, 100) <= 70) {
    // 跳过执行，延时5-15分钟
    sleep(rand(300, 900));
    return;
}
```

#### B. **每分钟执行频率限制**
```php
// 每分钟最多执行2个任务
if (当前分钟执行次数 >= 2) {
    // 等待到下一分钟
    sleep(等待时间);
}
```

#### C. **额外随机延时**
```php
// 饭点时间额外延时30-60秒
$randomDelay = rand(30, 60);
sleep($randomDelay);
```

## 📊 **实际效果对比**

### 正常时间（非饭点）：
```
队列中有100个任务
→ 100个任务正常执行
→ 平均每个任务延时8-20秒
→ 总执行时间：约13-33分钟
```

### 饭点时间（12:00-13:30）：
```
队列中有100个任务
→ 70%任务被跳过（70个任务延时5-15分钟）
→ 30%任务执行（30个任务）
→ 执行的任务每分钟最多2个
→ 每个任务额外延时30-60秒
→ 总执行时间：大幅延长，更分散
```

## ⚙️ **配置参数**

### 饭点时间Job执行控制配置：
```php
'lunch_time_control' => [
    'enable' => true,                   // 启用饭点控制
    'start_hour' => 12,                 // 开始时间12点
    'end_hour' => 13,                   // 结束时间13点
    'end_minute' => 30,                 // 结束分钟30分
    
    // Job执行层面的控制
    'max_tasks_per_minute' => 2,        // 每分钟最多2个任务
    'extra_delay_seconds' => 30,        // 额外延时30秒
    'skip_probability' => 70,           // 70%概率跳过
    'min_skip_delay' => 300,            // 跳过时最小延时5分钟
    'max_skip_delay' => 900,            // 跳过时最大延时15分钟
],
```

## 🎯 **控制逻辑流程**

### Job执行开始时：
```
1. 检查当前时间是否为饭点时间
   ↓
2. 如果是饭点时间：
   ├─ 70%概率：跳过执行，延时5-15分钟
   └─ 30%概率：继续执行
   ↓
3. 检查当前分钟执行次数
   ├─ 如果已达上限：等待到下一分钟
   └─ 如果未达上限：继续执行
   ↓
4. 记录当前分钟执行次数
   ↓
5. 添加额外延时30-60秒
   ↓
6. 开始正常Job执行流程
```

## 🎭 **行为模拟效果**

### 模拟真实用户饭点行为：
1. **大部分时间不操作**：70%的任务被跳过
2. **偶尔操作一下**：30%的任务执行
3. **操作频率很低**：每分钟最多2个任务
4. **操作比较慢**：额外延时30-60秒
5. **不规律性**：随机延时和跳过

### 对比效果：
- **优化前**：饭点时间执行频率与平时相同
- **优化后**：饭点时间执行频率大幅降低，更像真实用户

## 📈 **监控建议**

### 1. **执行频率监控**
- 统计饭点时间的任务执行数量
- 对比饭点与非饭点的执行频率
- 监控跳过执行的比例

### 2. **时间分布监控**
- 分析任务执行的时间分布
- 观察是否符合预期的低频率模式
- 检查延时效果是否合理

### 3. **效果评估**
- 评估饭点时间控制对整体进度的影响
- 分析是否需要调整控制参数
- 观察平台是否有异常检测

## ⚠️ **注意事项**

### 1. **执行进度影响**
- 饭点时间控制会显著降低执行速度
- 需要平衡隐蔽性和执行效率
- 可能需要延长总体执行时间

### 2. **队列积压**
- 饭点时间大量任务被延时
- 可能导致队列积压
- 需要监控队列长度

### 3. **时间设置**
- 饭点时间设置要符合实际情况
- 考虑不同地区的饭点时间差异
- 可以根据需要调整时间范围

通过这套饭点时间Job执行控制机制，可以在不影响任务生成的前提下，有效降低饭点时间的执行频率，更好地模拟真实用户的操作行为。
