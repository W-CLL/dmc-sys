# 标准推广饭点时间控制功能

## 功能概述

为标准推广Job（`AutoUpdateObjName.php` 和 `BaseUpdateStandJob.php`）添加了饭点时间控制功能，实现了与全域推广相同的时间段控制，但采用更保守的策略。

## 🎯 **设计理念**

### 差异化策略：
- **全域推广**：相对积极的饭点控制
- **标准推广**：更保守的饭点控制
- **原因**：标准推广通常更容易被检测，需要更谨慎的操作

## 📊 **控制参数对比**

### 全域推广 vs 标准推广：

| 控制项目 | 全域推广 | 标准推广 | 差异说明 |
|---------|---------|---------|---------|
| **跳过概率** | 70% | 80% | 标准推广多10%概率跳过 |
| **每分钟任务数** | 2个 | 1个 | 标准推广减少1个 |
| **额外延时** | 30-60秒 | 45-90秒 | 标准推广多15秒 |
| **跳过延时** | 5-15分钟 | 7-20分钟 | 标准推广多2-5分钟 |
| **等待时间** | 5-15秒 | 10-25秒 | 标准推广多5-10秒 |

## 🕐 **时间段控制**

### 支持的饭点时间：
- **午饭时间**：12:00-13:30
- **晚饭时间**：18:00-19:30
- **配置共享**：使用与全域推广相同的时间段配置

### 实际控制效果：
```
全域推广饭点时间：70%跳过，30%执行，每分钟最多2个
标准推广饭点时间：80%跳过，20%执行，每分钟最多1个
```

## 🎛️ **技术实现**

### 1. **独立的控制方法**
```php
// 标准推广专用的饭点控制方法
private function controlStandardMealTimeExecution($mealConfig, $currentMealPeriod)
{
    // 更保守的参数设置
    $maxTasksPerMinute = max(1, ($mealConfig['max_tasks_per_minute'] ?? 2) - 1);
    $skipProbability = min(90, ($mealConfig['skip_probability'] ?? 70) + 10);
    // ... 其他保守设置
}
```

### 2. **独立的Redis键**
```php
// 避免与全域推广冲突
$minuteKey = "standard_meal_tasks_minute_{$today}_{$currentMinute}";
```

### 3. **明确的日志标识**
```php
echo "【标准推广】{$mealName}随机跳过执行，延时 {$skipDelay} 秒\n";
```

## 🔧 **配置管理**

### 共享配置：
```php
// 标准推广使用相同的时间段配置
'meal_time_control' => [
    'time_periods' => [
        'lunch' => [...],   // 午饭时间
        'dinner' => [...],  // 晚饭时间
    ],
    // 基础参数（标准推广会在此基础上调整）
    'max_tasks_per_minute' => 2,
    'skip_probability' => 70,
    'extra_delay_seconds' => 30,
],
```

### 自动调整逻辑：
```php
// 标准推广自动应用更保守的设置
$maxTasksPerMinute = max(1, $基础值 - 1);      // 减少1个任务
$skipProbability = min(90, $基础值 + 10);      // 增加10%跳过概率
$extraDelay = $基础值 + 15;                   // 增加15秒延时
```

## 🎭 **行为模拟效果**

### 标准推广的饭点行为特点：
1. **更少操作**：80%概率跳过（vs 全域70%）
2. **更慢频率**：每分钟最多1个任务（vs 全域2个）
3. **更长延时**：45-90秒额外延时（vs 全域30-60秒）
4. **更长跳过**：7-20分钟跳过时间（vs 全域5-15分钟）

### 模拟真实用户差异：
- **全域推广用户**：相对活跃，饭点时间偶尔操作
- **标准推广用户**：更谨慎，饭点时间很少操作

## ⚠️ **注意事项**

### 1. **执行效率影响**
- 标准推广的饭点控制比全域推广更严格
- 整体执行时间会进一步延长
- 需要合理安排任务计划

### 2. **监控建议**
- 分别监控全域和标准推广的执行情况
- 对比两种推广方式的饭点控制效果
- 根据实际情况调整保守程度

### 3. **配置调优**
- 可以根据需要调整保守程度
- 可以为标准推广设置独立的配置参数
- 可以根据平台检测情况动态调整

## 📋 **总结**

通过为标准推广添加更保守的饭点时间控制，实现了：

1. **差异化策略**：标准推广比全域推广更保守
2. **统一管理**：共享时间段配置，简化管理
3. **独立控制**：避免相互影响，精确控制
4. **明确标识**：日志清晰区分，便于监控

现在系统可以根据不同的推广类型应用不同程度的饭点控制，更好地模拟真实用户的操作习惯，进一步提升操作的隐蔽性和安全性。
